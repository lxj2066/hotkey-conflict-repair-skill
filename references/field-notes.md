# 现场笔记：误判、反例与话术

> 这一份是踩过的坑。每条都写「看到什么现象、为什么、怎么回话」，不写原理科普。

## 一、探测为空闲，但用户坚持按了没反应

三种可能，按概率排：

1. **输入法或钩子类程序截走了按键**。它们不走热键注册表，探测看不见。处理：说明这一层查不到，给输入法设置的核查路径。
2. **目标软件自己没启用这个功能**。不是冲突，是软件里那个开关没开。处理：让用户先去软件设置里确认功能是开的。
3. **键盘硬件或按键被系统过滤**。极少见，先让用户用在线键盘测试页确认这个键本身有反应。

回话模板：「这个键在当前这台机器上是空闲的，说明没有程序在系统层面抢它。那多半是输入法或者软件自己没开，我们换个方向查。」

**不要**因为用户坚持就说「确实被占了」。探测结果是事实，用户感受也是事实，两者冲突时说明原因，不要顺着改结论。

## 二、探测为占用，但报的软件名不对

只报「疑似」的原因就在这里。同一组键可能是一个没在候选库里的软件注册的。判定链条是：

探测为占用 → 候选库给排查顺序 → 退出候选软件后复测 → 变空闲才算确认。

如果退完所有候选软件还是占用，就是「未知归属」，走人工识别：按托盘图标逐个退出常驻软件，每退一个复测一次。不要跳到「重装系统」「改注册表」。

## 三、装了 PowerToys 的机器

PowerToys Keyboard Manager 自己会拦组合，某些键在探测里显示空闲，实际上按下去已经被 PowerToys 吃掉了。遇到「探测空闲但按键确实被拦截」，先问一句「装没装 PowerToys」，装了就看它的 Keyboard Manager。

## 四、管理员权限不是必须的

热键表按桌面会话共享，普通权限就能探测到以管理员身份运行的程序注册的热键，不需要提权。不要建议用户「用管理员身份运行试试」，那是把权限当万能药。

## 五、同一组键反复被抢

用户装一个新软件，键又被抢走，这是常态而不是没修好。正确处置是记快照：记住上次的选择，下次复测时默认沿用，并提示「新装的某个软件可能又抢了这组键」。

不要在修完之后就给「永久解决」的承诺。可说的原话：「这次释放了。如果那个软件下次启动又抢回来，去它自己的设置里永久关掉，路径我一起给你了。」

## 六、不要碰的东西

| 想做的事 | 为什么不做 |
|---|---|
| 改注册表里的热键键值 | 键位分散在多个厂商分支下，改错会让软件起不来 |
| 卸载冲突软件 | 用户的软件不是我们的资产，删了没法回滚 |
| 关闭安全软件求「干净环境」 | 拿安全换便利，不接受 |
| 让用户装内核级热键工具 | 为一个截图键装驱动，风险收益不成比例 |
| 直接写别人的配置文件 | 软件下次启动覆盖，用户以为修好了其实没有 |

## 七、报告的措辞纪律

- 说「已被占用」，不说「被微信占用」，除非退出微信后复测过。
- 说「疑似」，不说「就是」。
- 说「系统保留，改不了」，不说「暂不支持」。
- 说「这一步需要你点一下」，不说「正在为你自动修复」。
- 修完必须复测一次再说「已修复」，没复测就说「已释放，待复测」。

## 八、扫描范围的可控性

默认扫候选库里的二十来组常用键，几秒完成。用户要查某个具体组合时，加 `--combos` 传入即可，不必全键盘暴力扫。全键盘扫（所有修饰组合 × 所有键位）会产生几百次注册试探，收益低且容易误报，不做。

## 九、复测的价值

复测不是形式。释放后目标软件可能重启就抢回来，复测结果直接决定话术：变空闲说「已修复」，仍然占用说「已释放但可能被抢回，去它设置里永久关」。

复测就是再跑一次 `scripts/hk_probe.py`，与上一次的 `probe.json` 对齐看同一个组合的状态变化，不要只看总数。
